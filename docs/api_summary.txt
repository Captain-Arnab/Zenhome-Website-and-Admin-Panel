2. LEGACY ENDPOINTS AND LEGACY_STRICT_AUTH BEHAVIOUR
   LEGACY_STRICT_AUTH (api/legacy_access.php) applies to the legacy customer-app endpoints. Default false: no auth, every call
   is only logged to legacy_access_log. true: valid customer Bearer token required (401), user_id must be the caller (403),
   rows of other customers answer 404. Legacy admin endpoints (api/admin/*.php) ignore the flag: they always require an admin
   session (+CSRF on non-GET), admin Bearer token or Admin-Token header (= ADMIN_SECRET), via api/admin/core/legacy_guard.php.
   - api/admin/login.php: flag not used; public admin login issuing a 30-day admin Bearer token (no lockout).
   - api/admin/assignTechnician.php: auth: Admin session or Admin Bearer or Admin-Token header
   - api/admin/confirm_bookings.php: auth: Admin session or Admin Bearer or Admin-Token header
   - api/admin/fetch_bookings.php: auth: Admin session or Admin Bearer or Admin-Token header
   - api/admin/manageTimeSlot.php: auth: Admin session or Admin Bearer or Admin-Token header
   - api/book_appointment.php: strict=true: customer token (401) + body user_id must be caller (403). strict=false: anyone can book for any user_id.
   - api/checkSlot.php: strict=true: customer token only (401), no ownership check. strict=false: open.
   - api/serviceBooking.php: strict=true: token (401) + body user_id must be caller (403). strict=false: open.
   - api/serviceComplete.php: strict=true: token (401) + user_id must be caller (403) + booking id must belong to caller, missing allowed (404). strict=false: anyone can complete any booking.
   - api/admin/addService.php: auth: Admin session or Admin Bearer or Admin-Token header
   - api/admin/priceService.php: auth: Admin session or Admin Bearer or Admin-Token header
   - api/admin/removeService.php: auth: Admin session or Admin Bearer or Admin-Token header
   - api/fetchCategory.php: strict=true: customer token only (401). strict=false: open.
   - api/admin/deactivate_user.php: auth: Admin session or Admin Bearer or Admin-Token header
   - api/admin/fetch_users.php: auth: Admin session or Admin Bearer or Admin-Token header
   - api/admin/remove_user.php: auth: Admin session or Admin Bearer or Admin-Token header
   - api/admin/orders.php: auth: Admin session or Admin Bearer or Admin-Token header
   - api/order_details.php: strict=true: token (401) + order_id row must belong to caller, missing row allowed (404). strict=false: any order readable.
   - api/user_orders.php: strict=true: token (401) + GET user_id must be caller (403). strict=false: any user's orders readable.
   - api/admin/payments.php: flag not used; legacy mode (no action) requires Admin-Token header = ADMIN_SECRET only.
   - api/fetch-transaction.php: strict=true: token (401) + transaction_id must exist and belong to caller (404). strict=false: any transaction readable.
   - api/payementInitiate.php: strict=true: token (401) + body user_id must be caller (403). strict=false: payment can be initiated for any user_id.
   - api/paymentConfirmation.php: strict=true: token (401) + transactionId must exist and belong to caller (404). strict=false: any transaction status readable.
   - api/save_transaction.php: strict=true: token (401) + user_id must be caller (403) + transaction must belong to caller, missing allowed (404). Status can still be set to success without PhonePe check. strict=false: anyone can write any transaction.
   - api/user_transaction.php: strict=true: token (401) + user_id (body or GET) must be caller (403). strict=false: any user's transactions readable.
